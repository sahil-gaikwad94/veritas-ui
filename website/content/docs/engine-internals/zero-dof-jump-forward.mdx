Zero-DoF (Zero Degrees of Freedom) is Veritas's most powerful optimization. It **deterministically computes derived fields and splices them into the token stream** — the LLM never samples them, saving `_T_ − 1` LLM forward passes per derived field.

---

## The Problem: LLM Guessing Arithmetic

Without Zero-DoF, if you want `expected_return = dot(weights, RETURNS)`, the LLM has to generate `expected_return` token by token, guessing each digit. Even a small error propagates to downstream calculations like Sharpe ratio.

With standard JSON mode, you'd get:
```json
{
  "weights": {"AAPL": 0.40, "MSFT": 0.35, "NVDA": 0.25},
  "expected_return": 0.2100,  ← LLM guessed this — probably wrong
  "sharpe_ratio": 1.214       ← LLM guessed this — probably wrong
}
```

With Zero-DoF:
```json
{
  "weights": {"AAPL": 0.40, "MSFT": 0.35, "NVDA": 0.25},
  "expected_return": 0.1615,  ← Veritas computed this exactly
  "sharpe_ratio": 0.5945      ← Veritas computed this exactly
}
```

---

## `ZeroDofRule`

### What It Does

`ZeroDofRule` monitors the decode state. When all input variables for a `derive` constraint have been emitted, it computes the target value deterministically and injects it into the JSON stream.

### How It Works

1. The `DependencyGraph` knows which fields each derived field depends on
2. The key ordering puts inputs before outputs
3. The PDA detects when all inputs for a derived field are complete
4. `ZeroDofRule` triggers: the value is computed deterministically (native path when available) and spliced into the byte stream
5. The LLM never sees the derived field — it's injected directly

### Example

<CodeBlock language="text" title="what the splice looks like in the decode trace" code={`state   weights.AAPL=0.40  weights.MSFT=0.35  weights.NVDA=0.25   (all emitted)
rule    derive(expected_return == dot(weights, RETURNS))
status  READY — dependencies satisfied, zero degrees of freedom

action  splice '\"expected_return\": 0.1615'
value   0.40*0.14 + 0.35*0.13 + 0.25*0.24 = 0.1615
calls   0 LLM forward passes
tokens  0 sampled — the bytes are written directly`} copyable />

Zero-DoF is a property of the **dependency graph**, not a special case in the decoder: once every
input of a derived field has a concrete value, that field can be written without asking the model.

## `build_json_key_order`

### What It Does

Topologically sorts JSON keys using the `DependencyGraph` so that **inputs always precede outputs**. This ordering is what makes Zero-DoF splicing possible.

### Example

<CodeBlock language="text" title="canonical key order" code={`order = build_json_key_order(spec)

## Benefits of Zero-DoF

| Metric | Without Zero-DoF | With Zero-DoF |
| :--- | :--- | :--- |
| LLM forward passes per derived field | 1+ (LLM guesses each digit) | **0** (computed deterministically) |
| Numerical guessing | Possible | **Impossible** |
| Token latency per derived field | ~50–100 ms of sampling | **≈ 0** (no forward pass) |
| Conservation law violations | Possible | **Impossible** |
| Derived field accuracy | Approximate | **Exact** |

<Callout variant="check" title="Saves T − 1 Forward Passes">

For each derived field, Veritas saves `_T_ − 1` LLM forward passes — where `_T_` is the number of tokens the LLM would have needed to guess the value correctly.

If a derived field would take 20 tokens to guess, Zero-DoF saves 19 forward passes per field. With 3 derived fields, that's 57 forward passes saved per decode.

</Callout>

## Complete Example

<CodeBlock language="python" code={`import veritas as vt

RETURNS = {\"AAPL\": 0.14, \"MSFT\": 0.13, \"NVDA\": 0.24}
RISK_FREE = 0.04

@vt.verified_schema()
def portfolio(p: Portfolio):
    vt.require(vt.sum(p.weights.values()) == 1.0, tol=1e-6)
    vt.require(vt.forall(p.weights.values(), lambda w: (0.05 <= w) & (w <= 0.50)))

    # These are Zero-DoF — computed by Veritas, not guessed by LLM
    vt.derive(p.expected_return == vt.dot(p.weights, RETURNS), tol=1e-5)
    vt.derive(p.volatility == vt.sqrt(vt.quad_form(p.weights, COV)), tol=1e-5)
    vt.derive(p.sharpe_ratio == (p.expected_return - RISK_FREE) / p.volatility, tol=1e-5)

    vt.require(p.sharpe_ratio >= 0.55)

# When decoded:
# 1. LLM generates weights: {\"AAPL\": 0.40, \"MSFT\": 0.35, \"NVDA\": 0.25}
# 2. Veritas computes expected_return = 0.1615 (Zero-DoF splice)
# 3. Veritas computes volatility = 0.2044 (Zero-DoF splice)
# 4. Veritas computes sharpe_ratio = 0.5945 (Zero-DoF splice)
# 5. LLM generates nothing more — document is complete

# Result: 3 derived fields, 0 LLM calls for them`} copyable />

## Token Classification

Every token in a Veritas decode is one of three types:

| Type | Meaning | Example |
| :--- | :--- | :--- |
| `sample` | Sampled by the model, after PDA + HC4 masking | `0`, `4`, `.`, `"` |
| `splice` | Written deterministically once inputs are ready | `0.1615` |
| `backtrack` | CDCL rewound the stream after an UNSAT branch | rewind to `weights.NVDA` |
