Tier 0 is the outermost ring of Vexx's three-tier solver horizon. It's a **JSON Pushdown Automaton (PDA)** — a state machine that tracks JSON grammar structure as tokens are generated, ensuring the output is always syntactically valid JSON.

---

## What Is a Pushdown Automaton?

A PDA is a finite state machine with a stack. It's more powerful than a regular expression because it can track nested structures — exactly what JSON needs (objects inside objects, arrays inside arrays, etc.).

### How the PDA Works During Decoding

As the LLM generates each token:

1. **Read** the token
2. **Update** the internal stack (track nesting depth, current context)
3. **Compute** valid next tokens based on JSON grammar
4. **Mask** all invalid tokens to `-inf` (negative infinity logits)

### Example: Tracking JSON Structure

```json
{
  "weights": {
```

At this point, the PDA knows:

| PDA State | Meaning |
| :--- | :--- |
| Stack depth: 2 | Inside outer object `{` and inner object `{"weights": {` |
| Current context: Inside object, after `:` | Expecting a value for key `"weights"` |
| Valid next tokens: | `"AAPL"`, `"MSFT"`, `"NVDA"`, `{`, `}` |
| Invalid (masked): | `[`, `]`, `0-9`, `true`, `false`, `null`, `,` |

The PDA ensures the LLM can never produce invalid JSON syntax — every token it samples is guaranteed to keep the document structurally valid.

## `JSONPushdownAutomaton`

The automaton is the main interface. Construct one per decode, feed decoded token text, and ask for
structure at any point. It is deterministic, cloneable and has no model dependency.

### API

| Member | Signature | Description |
| :--- | :--- | :--- |
| `feed(text)` | `(str) -> bool` | Advance the machine; `False` on a syntax error |
| `step(ch)` | `(str) -> bool` | Advance by one character |
| `depth` | `int` (property) | Current nesting depth |
| `state` | `str` | Current grammar state |
| `stack` | `list[dict]` | Container stack with key roles |
| `accepts()` | `() -> bool` | Prefix can still be completed |
| `finish()` | `() -> bool` | Close pending numbers/literals, then check completeness |
| `clone()` | `() -> JSONPushdownAutomaton` | Copy for speculative decoding |
| `error` | `str | None` | First syntax error, if any |

### Example

<CodeBlock language="python" title="feed a prefix and inspect the state" code={`from vexx import JSONPushdownAutomaton

machine = JSONPushdownAutomaton()

for chunk in ['{', '"weights"', ':', '{"AAPL": 0.4']:
    if not machine.feed(chunk):
        raise ValueError(machine.error)

print(machine.depth)          # 2
print(machine.state)          # inside an object, expecting a value
print(machine.accepts())      # True — the prefix is still extendable
print(machine.current_key_role())

closed = machine.clone()
assert closed.feed('}') and closed.feed('}')
assert closed.accepts()

bad = JSONPushdownAutomaton()
assert not bad.feed('}')      # closing without opening
print(bad.error)`} copyable />

## `TokenMasker`

### What It Does

The `TokenMasker` converts the PDA's valid-token set into a logit mask tensor that can be applied to LLM logits before sampling.

### How It Works

1. PDA computes which tokens are valid next
2. `TokenMasker` creates a float32 tensor of size `vocab_size`
3. Valid tokens get `0.0` (no change to logits)
4. Invalid tokens get `-inf` (impossible to sample)
5. The mask is added to LLM logits before softmax sampling

<Callout variant="check" title="Performance: 0.23 ms per step">

`TokenMasker.valid_mask` runs in **0.23 milliseconds** in Rust — 17.9x faster than the Python reference implementation (4.07 ms). This is fast enough to run on every single token without adding noticeable latency to LLM generation.

</Callout>

## Incremental prefix status

For streaming you do not need a second parser. `vexx.native.prefix_status` classifies the prefix with
the same automaton (native when available, Python otherwise) and returns a string, not a dict.

<CodeBlock language="python" title="know when the document is complete" code={`import vexx.native as native

buffer = ""
for chunk in token_stream:
    buffer += chunk
    status = native.prefix_status(buffer)     # 'incomplete' | 'complete' | 'invalid'
    if status == "invalid":
        abort(buffer)
    if status == "complete":
        emit(buffer)
        break`} copyable />

`native.canonical_document(text)` returns a canonical rendering for a complete document, or `None` when
the text is not valid JSON.

## `TokenHealer`

BPE splits text in places JSON does not care about: `0.25` may tokenize as `["0.2", "5"]`. `TokenHealer`
finds the minimal KV-cache backup that lets a spliced string tokenize exactly, and reports whether it
succeeded instead of pretending.

<CodeBlock language="python" title="a splice across a token boundary" code={`from vexx import TokenHealer

healer = TokenHealer()          # ByteTokenizer by default
prefill = healer.heal('{"w', 'eight": 0.25}', max_backup=4)

print(prefill.backup_tokens)    # tokens to rewind from the KV cache
print(prefill.new_token_ids)    # ids to append after the rewind
print(prefill.exact)            # True only when the boundary was reproduced exactly
print(prefill.healed_text)      # full text after healing

# exact=True  -> the tokenizer agrees end to end
# exact=False -> text-level splice only; never claim exact healing`} copyable />

Splicing is only sound when `exact` is true. Otherwise the engine writes text and re-tokenizes, which
costs a forward pass but keeps the stream consistent.
