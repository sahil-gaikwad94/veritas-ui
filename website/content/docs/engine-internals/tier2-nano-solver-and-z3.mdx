Tier 2 is the core ring of Vexx's three-tier solver horizon. It provides **exact linear solving** for feasibility checks and contradiction detection — used by the pre-flight gate and CDCL jumpback engine.

---

## What Is Tier 2?

While Tier 0 (PDA) ensures valid JSON syntax and Tier 1 (HC4/AF2) narrows numeric prefixes, Tier 2 provides **exact mathematical solving** for questions like:

- "Are all my constraints mutually satisfiable?"
- "What's the exact solution to this linear system?"
- "Which field caused this UNSAT conflict?"

Tier 2 never runs per token — it runs at schema compile time (pre-flight) and on conflict detection (CDCL).

## `VexxNanoSolver`

### What It Does

`VexxNanoSolver` is a dependency-free reference decision procedure for linear and difference constraints, using **bounded Fourier–Motzkin elimination** over exact `Fraction` arithmetic. Pure Python — no Z3, no solver dependency — and the module says what it is: a reference procedure, not a dual-simplex engine.

### Fourier-Motzkin Elimination

Fourier-Motzkin is a variable elimination algorithm for linear systems:

1. Pick a variable to eliminate (e.g., `x`)
2. Split constraints into three groups: `x <= c`, `x >= c`, `x == c`
3. Combine each upper bound with each lower bound to create new constraints without `x`
4. Repeat until all variables eliminated or a contradiction is found

### Example

<CodeBlock language="python" code={`from vexx import VexxNanoSolver, SolverStatus

# Rational linear feasibility over named variables
solver = VexxNanoSolver()
solver.assert_constraint(("eq", {"aapl": 1, "msft": 1, "nvda": 1}, 1.0))   # fully invested
for name in ("aapl", "msft", "nvda"):
    solver.assert_constraint(("ge", {name: 1}, 0.05))
    solver.assert_constraint(("le", {name: 1}, 0.50))

solver.check()                    # SolverStatus.SAT
solver.get_float_model()          # {'nvda': 0.275, 'msft': 0.275, 'aapl': 0.1}

# A contradiction yields an unsat core instead of a model
bad = VexxNanoSolver()
bad.assert_constraint(("ge", {"x": 1}, 8))
bad.assert_constraint(("le", {"x": 1}, 3))
bad.check()                       # SolverStatus.UNSAT
bad.get_unsat_core()              # [0, 1]`} copyable />

### When to Use NanoSolver vs. Z3

| Use NanoSolver when... | Use Z3 when... |
| :--- | :--- |
| Constraints are purely linear | Constraints are non-linear (quadratic, etc.) |
| You need zero external dependencies | You need quantified formulas (forall/exists) |
| Speed is critical (per-solve, not per-token) | You need SMT-LIB2 proof certificates |
| Working with real numbers only | Working with integers, bitvectors, etc. |

## `SmtBridge` & `Z3SmtOracle`

### What They Do

For non-linear or quantified constraints, Vexx bridges to **Microsoft Z3** via `SmtBridge`. The `Z3SmtOracle` is used only as a fallback — the common case (linear constraints) is handled by the nano-solver.

### Architecture

```
Your Constraint
       ↓
┌───────────────┐
│ VexxNanoSolver │ ← Pure Rust, no dependencies
│ (linear only)   │
└───────────────┘
       ↓ (if non-linear or quantified)
┌───────────────┐
│   SmtBridge   │ ← PyO3 bridge to Z3
│   Z3SmtOracle │ ← Z3 theorem prover
└───────────────┘
```

<Callout variant="info" title="Z3 Is Optional">

Z3 is only needed for non-linear/quantified SMT. Install with:

```
pip install "vexx-ai[z3]"
```

The core engine never calls Z3 per token — Tier 0 and Tier 1 handle all per-token work.

</Callout>

## Pre-Flight Exact Feasibility

The pre-flight gate uses Tier 2 for **exact affine feasibility checking** — proving that all constraints are mutually satisfiable before any tokens are generated.

### What It Checks

1. **Linear feasibility** — Can all linear constraints be satisfied simultaneously?
2. **Bound consistency** — Do interval bounds conflict with linear constraints?
3. **Derivation consistency** — Do `derive` statements form a valid DAG (no cycles)?

### Example

<CodeBlock language="python" code={`import vexx as vx

# This spec is infeasible: sum(x) == 1 with every x <= 0.10 over 6 variables
try:
    from infeasible_spec import weights          # pre-flight runs at import
except vx.InfeasibleSpecError as exc:
    print(exc.conflicts)                        # [0, 1]
    print(exc.relaxation["suggestion"])         # 'Relax a listed constraint or a field bound.'

# The same check without the exception path
report = vx.run_preflight(spec)
report.status        # 'UNSAT' | 'SAT' | 'UNKNOWN'
report.is_sat        # True only when a witness was constructed and checked
report.details       # ['exact rational linear relaxation is infeasible', ...]

# Tier 2 proved this without any LLM tokens`} copyable />
