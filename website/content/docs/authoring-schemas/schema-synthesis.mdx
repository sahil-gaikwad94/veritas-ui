Point `vexx synth` at a handful of real payloads and it writes a runnable `@vx.verified_schema`
module: types, defaults, numeric ranges, key sets and per-container value bounds. The deterministic
half of schema authoring — no model, no guessing, and an explicit refusal to invent constraints.

## What it will and will not infer

<KeyValueTable
  rows={[
    { key: 'Types and defaults', value: 'int, float, str, bool, null', note: 'Optional[...] when a value is ever null; first sample becomes the default' },
    { key: 'Numeric ranges', value: 'int exact, float padded ±10%', note: 'Only with two or more samples and a non-zero spread' },
    { key: 'Dict key sets', value: 'keys_subset(p.field, [...])', note: 'The union of keys seen across samples' },
    { key: 'Dict value bounds', value: 'forall(field.values(), ...)', note: 'Padded ±10% over the union of numeric values' },
    { key: 'Conservation laws', value: 'never', note: 'A sum of 1.0 across samples is a coincidence until you assert it' },
    { key: 'Derived expressions', value: 'never', note: 'Use derive() by hand: inference cannot know the formula is intended' },
  ]}
/>

<Callout variant="warn" title="A synthesiser that guesses is worse than none">
The module docstring says it plainly: *it never invents constraints that the examples do not support*.
Anything structural — conservation laws, `derive` expressions, conditional rules — stays your call, which
is why the generated file is a first draft you review, not a spec you ship.
</Callout>

## A real run

<CodeBlock language="bash" title="three payloads, one module" code={`$ cat port_examples.json
[
  {"weights": {"AAPL": 0.40, "MSFT": 0.35, "NVDA": 0.25}, "sharpe": 0.59},
  {"weights": {"AAPL": 0.30, "MSFT": 0.45, "NVDA": 0.25}, "sharpe": 0.61},
  {"weights": {"AAPL": 0.55, "MSFT": 0.20, "NVDA": 0.25}, "sharpe": 0.66}
]

$ vexx synth --from-json port_examples.json --name Portfolio --out port_schema.py
wrote port_schema.py`} copyable />

<CodeBlock language="python" title="port_schema.py, generated verbatim" code={`"""Synthesized by vexx from concrete examples. Review before production use."""

from __future__ import annotations

from typing import Any, Optional

import vexx as vx
from pydantic import BaseModel, Field


class Portfolio(BaseModel):
    weights: dict[str, float] = Field(default_factory=dict)
    sharpe: float = 0.59


@vx.verified_schema()
def portfolio(p: Portfolio):
    vx.require(vx.keys_subset(p.weights, ['AAPL', 'MSFT', 'NVDA']))
    vx.require(vx.forall(p.weights.values(), lambda v: (0.165 <= v) & (v <= 0.585)))
    vx.require((0.583 <= p.sharpe) & (p.sharpe <= 0.667))`} copyable />

Note the arithmetic: the observed weight range was `0.20 … 0.55`, and the float bounds are padded by 10%
of that spread → `0.165 … 0.585`. Integers are never padded.

## Options

<KeyValueTable
  rows={[
    { key: '--from-json <file>', value: 'examples', note: 'A JSON object or a non-empty array of objects — not JSONL' },
    { key: '--out <file>', value: 'write the module', note: 'Omit to print the source to stdout' },
    { key: '--name <name>', value: 'class name', note: 'Defaults to Synthesized; CamelCase and snake_case are derived from it' },
    { key: '--no-ranges', value: 'types only', note: 'Skips every inferred require(), keeping the model shape' },
    { key: '--from-doc <file>', value: 'refused in this build', note: 'error: --from-doc requires a model adapter' },
  ]}
/>

There is no `--json` mode and no `--tolerance`/`--min-samples`/`--conservation-laws` flag: the output is
a Python module, and the padding rule is fixed.

## From Python

`vx.synth` returns the same source text without touching the filesystem:

<CodeBlock language="python" code={`import vexx as vx

source = vx.synth(samples=[{"qty": 2, "price": 19.5}, {"qty": 5, "price": 4.25}])
print(source)          # a complete module, ready to write to disk or exec`} copyable />

<Callout variant="tip" title="What to add by hand">
The generated module is where your intent starts. Add the parts inference cannot see — `sum(weights) == 1`,
`derive(expected_return == dot(...))`, a quality threshold, a `pattern` on an identifier — then run
`python -m vexx check-spec` and read the verdict before wiring it into a decode.
</Callout>

## Limitations

| Limit | Why |
| :--- | :--- |
| Ranges need two samples | One value is a point, not a range — and copying it would forbid every other input |
| No conservation laws | Summing to 1.0 in three samples says nothing about sample four |
| No derived expressions | A `derive` that is merely correlated with the data is a bug waiting to pass |
| Flat key sets | Nested objects become `dict[str, T]`; per-key schemas inside them are not generated |
| Not JSONL | The loader calls `json.loads` on the file, so use one JSON array |
