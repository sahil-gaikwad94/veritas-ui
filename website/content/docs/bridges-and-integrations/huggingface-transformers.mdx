`transformers` accepts a `LogitsProcessor` in `generate()`. Veritas ships one that builds an exact mask
from the tokenizer vocabulary and applies it at every step.

<CodeBlock language="python" title="a generate() call" code={`from transformers import AutoModelForCausalLM, AutoTokenizer
from veritas.bridges import VeritasLogitsProcessor

model_id = "meta-llama/Llama-3.1-8B-Instruct"
tokenizer = AutoTokenizer.from_pretrained(model_id)
model = AutoModelForCausalLM.from_pretrained(model_id)

processor = VeritasLogitsProcessor.from_spec(portfolio, tokenizer=tokenizer)
inputs = tokenizer("produce a portfolio", return_tensors="pt")
output = model.generate(
    **inputs,
    max_new_tokens=512,
    do_sample=True,
    temperature=0.7,
    logits_processor=[processor],
)
text = tokenizer.decode(output[0][inputs["input_ids"].shape[-1]:], skip_special_tokens=True)

portfolio.verify(text).raise_if_failed()`} copyable />

<Callout variant="info" title="Prompt length matters">
The processor reconstructs the generated prefix from `input_ids`. Set `prompt_len` when you batch
prompts of different lengths, or the prefix will include prompt tokens that are not JSON. Passing
`eos_token_id` explicitly is safer than relying on the tokenizer default.
</Callout>

## Bridge convenience

## Adapter status

The processor works with any tokenizer exposing `get_vocab`/`convert_ids_to_tokens` and a decoded
vocabulary; unusual tokenizers may need an explicit `vocabulary=` list. Masking is exact over that
vocabulary, but it is a Python reference implementation — expect milliseconds, not microseconds, per
step unless the native accelerator is loaded.

Bridges are adapter-tested with fakes. Validate one prompt end to end before trusting a new model or
tokenizer.
