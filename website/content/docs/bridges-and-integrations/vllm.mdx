vLLM accepts logits processors per request. Vexx supplies one that masks every token against the
JSON grammar — and against your schema when a spec is supplied.

## API

<KeyValueTable
  rows={[
    { key: 'VLLMLogitsProcessor(tokenizer=None, spec=None, vocabulary=None, eos_token_id=None)', value: 'callable logits processor' },
    { key: 'VexxVLLMBridge(model=None, spec=None, tokenizer=None)', value: 'bridge object' },
    { key: 'bridge.sampling_params()', value: '{"logits_processors": [processor]}' },
    { key: 'bridge.patch(engine=None)', value: 'appends to host list, or raises TypeError' },
    { key: 'patch_vllm(engine, spec=None, tokenizer=None)', value: 'one-line patch' },
  ]}
/>

<CodeBlock language="python" title="pass the processor through SamplingParams" code={`from vllm import LLM, SamplingParams
from vexx.bridges import VexxVLLMBridge

model = LLM(model="meta-llama/Llama-3.1-8B-Instruct")
bridge = VexxVLLMBridge(model, spec=portfolio, tokenizer=model.get_tokenizer())

params = SamplingParams(temperature=0.7, max_tokens=512, **bridge.sampling_params())
outputs = model.generate(["produce a portfolio"], params)

# the mask enforced grammar + spec during generation
report = portfolio.verify(outputs[0].outputs[0].text)
report.raise_if_failed()`} copyable />

## Patching an engine

<CodeBlock language="python" title="mutating an existing host" code={`from vexx.bridges import patch_vllm

try:
    patch_vllm(model, spec=portfolio, tokenizer=model.get_tokenizer())
except TypeError as exc:
    # host has no logits_processors list — use sampling_params() instead
    print(exc)`} copyable />

<Callout variant="warn" title="Fail closed">
`patch()` raises `TypeError` when the host exposes no logits processor list rather than silently
running unconstrained. Prefer the explicit `sampling_params()` path; it survives vLLM version changes
better than attribute patching.
</Callout>

## Adapter status

The bridge is tested with deterministic fake tokenizers and hosts, not against a live vLLM deployment.
Tokenizer vocabulary extraction varies by version — verify one request end to end before relying on the
mask in production, and keep `report.raise_if_failed()` as the last line of defence.

## What the mask does not do

- It does not call the model or manage sampling parameters other than the processor.
- It does not verify the final object — do that with `spec.verify(...)`.
- With no `spec`, the processor enforces JSON grammar only (no cross-field constraints).
