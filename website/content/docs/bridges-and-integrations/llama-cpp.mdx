llama.cpp hosts come in two shapes: those that accept a Python logits processor, and those that only
accept a GBNF grammar string. The bridge handles both — and **refuses** the grammar-only path when you
supply a spec, because a generic JSON grammar cannot enforce your constraints.

<CodeBlock language="python" title="grammar for the host" code={`from llama_cpp import Llama
from veritas.bridges import LlamaCppBridge

model = Llama(model_path="./model.gguf", n_ctx=4096)

# No spec: a generic JSON grammar is safe to hand over

<CodeBlock language="python" title="spec-aware host" code={`from veritas.bridges import patch_llamacpp

patch_llamacpp(model, spec=portfolio, tokenizer=my_tokenizer)`} copyable />

<Callout variant="warn" title="Why the grammar path fails closed">
A GBNF grammar describes syntax. If the host can only accept grammar, there is no way to apply interval
contraction or zero-DoF splicing. Passing a spec in that situation raises instead of pretending the
constraints are enforced.
</Callout>

## Adapter status

Adapter-tested with fakes; llama.cpp Python bindings differ by build. Confirm that your host exposes
`set_logits_processor` before promising spec enforcement, and always re-verify the returned object.
