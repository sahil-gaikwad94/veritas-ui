When you cannot touch logits, verification happens after the response. `patch_openai` wraps a client,
requests a JSON schema, verifies the body and raises before a bad value reaches your code.

<KeyValueTable
  rows={[

    { key: 'from_openai(client, mode, spec=None)', value: 'no-op unless mode is veritas' },
    { key: 'InstructorBridge(client=None, spec=None, mode=INSTRUCTOR_MODE)', value: '.create(**kwargs)' },
    { key: 'VerificationError(message, report=None, response=None)', value: 'raised on FAIL / INCOMPLETE' },
    { key: 'vt.from_outlines(model, spec=None)', value: 'OutlinesAdapter with .generate(prompt)' },

<CodeBlock language="python" title="wrap an OpenAI-compatible client" code={`from openai import OpenAI
from veritas.bridges import patch_openai, VerificationError

client = patch_openai(OpenAI(), spec=portfolio)

try:
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": "propose a portfolio"}],
    )
    print(response.veritas_report.status)     # PASS
except VerificationError as exc:
    print(exc.report.constraints)             # what failed, field by field`} copyable />

The proxy sets `response_format` to a JSON schema and injects `veritas_vir` into `extra_body` so a
compatible server can enforce the spec server-side. Any other attribute is delegated to the wrapped
client unchanged.

<Callout variant="warn" title="Post-hoc is a guard, not a decoder">
The provider has already sampled the tokens. A violation costs the whole response and a retry. Use a
logits-processor bridge (vLLM, SGLang, HF) when prevention matters, and keep this path for providers you
do not control.
</Callout>

## Outlines

`OutlinesAdapter` is a thin route into `vt.generate` — it does not reimplement Outlines. Use it when your
Outlines-backed model can expose next-token logits:

<CodeBlock language="python" code={`import veritas as vt

adapter = vt.from_outlines(model, spec=portfolio)
result = adapter.generate("propose a portfolio")
print(result.raw, result.report.status)`} copyable />

## Guidance and LMQL

This release has **no Guidance or LMQL adapters**. Earlier drafts of this page described them; there is
no module, test or entry point behind that claim. If you need those runtimes, drive them with a JSON
schema plus `spec.verify(...)` and treat the result as post-hoc verification.

## Adapter status

Tested with deterministic fake clients: request shaping, schema injection and violation raising. Not
tested against live vendor endpoints, which may reject unknown `extra_body` keys — confirm with your
provider before enabling the spec injection in production.
