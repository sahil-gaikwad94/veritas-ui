Veritas needs **Python 3.11+**. The core package has three runtime dependencies — `pydantic>=2.0`,
`jsonschema>=4.18` and `sqlglot>=25` — and no mandatory Rust toolchain.

<Callout variant="warn" title="PyPI status">
The distribution metadata ships as `veritas-ai`, but the release is not on PyPI yet. Install directly
from GitHub until that changes; the commands below already use the supported path.
</Callout>

## Install from GitHub

<CodeBlock language="bash" title="one-line install from the main branch" code={`pip install "git+https://github.com/sahil-gaikwad94/veritas.git"

# confirm the interpreter can see it
python -c "import veritas; print(veritas.__version__)"   # 2.0.0`} copyable />

## Editable install (recommended for development)

<CodeBlock language="bash" title="clone + editable install" code={`git clone https://github.com/sahil-gaikwad94/veritas.git
cd veritas

python -m venv .venv
.venv/bin/pip install -e ".[dev]"

.venv/bin/python -m pytest tests/ -q
.venv/bin/veritas --help`} copyable />

If you prefer not to install while exploring the source tree, set `PYTHONPATH=python` and run modules
directly:

```bash
PYTHONPATH=python python -m veritas doctor
```

With a direct Git reference, a PEP 508 requirement string is the least ambiguous form:

<CodeBlock language="bash" title="extras from GitHub" code={`pip install "veritas-ai[z3] @ git+https://github.com/sahil-gaikwad94/veritas.git"
pip install "veritas-ai[cas] @ git+https://github.com/sahil-gaikwad94/veritas.git"
pip install "veritas-ai[rl] @ git+https://github.com/sahil-gaikwad94/veritas.git"`} copyable />

Inside an editable clone, the short form works:

```bash
.venv/bin/pip install -e ".[z3]"
```

## Confirm what is actually running

<CodeBlock language="bash" title="engine diagnostics" code={`python -m veritas doctor           # human readable
python -m veritas doctor --json    # paste into a bug report
python -m veritas doctor --strict  # exit 1 unless the native extension is loaded`} copyable />

On a default install — no Rust toolchain, no compiled wheel — the real output is:

```text
veritas 2.0.0 on CPython 3.11.2
  engine    reference python
  reason    ModuleNotFoundError: No module named 'veritas_py'
  wire      n/a
  platform  Linux-6.1.158+-x86_64-with-glibc2.36
  note      the pure-Python engine is complete; the extension would only be faster.
```

That `reason` line is not a warning: the reference engine is the complete product. When the optional
wheel is installed the `engine` line becomes `<name> <version> (<abi>)` from `veritas.native.info()`,
`wire` reports the negotiated wire version instead of `n/a`, and the `reason` and closing `note` lines
disappear. `--strict` exists for deployment health checks: it exits 1 unless the accelerator is live.

The same facts are available in Python — and this is the shape you can assert on:

```python
import veritas

veritas.native.available()  # False on a default install
veritas.native.info()
# {'name': 'python', 'version': 'pure', 'wire_version': None,
#  'native_available': False,
#  'load_error': "ModuleNotFoundError: No module named 'veritas_py'"}

veritas.doctor()
# {'version': '2.0.0', 'python': 'pure',
#  'engine': {'name': 'python', 'version': 'pure', 'wire_version': None,
#             'native_available': False, 'load_error': "..."},
#  'wire_version': None}
```

<Callout variant="info" title="The Python engine is the product">
The Rust core is an accelerator, not a separate implementation you must trust. Python remains
authoritative for every behaviour, and every native wrapper falls back to it. A native regression can
cost speed; it should never cost soundness.
</Callout>

## Environment variables

| Variable | Effect |
| :--- | :--- |
| `VERITAS_NO_NATIVE=1` | Force pure-Python execution for every call. Checked per call — no reinstall, no restart. |
| `PYTHONPATH=python` | Run from a source checkout without installing (development only). |

```bash
# A/B a suspected accelerator bug without touching the environment
VERITAS_NO_NATIVE=1 python -m pytest tests/test_native_backend.py -q
```

## Verify the install

<CodeBlock language="bash" title="the suite that matters" code={`python -m pytest tests/ -q

# default install:        378 passed, 41 skipped
# native extension built: 419 passed, 0 skipped`} copyable />

The 41 skips are the native/pure-Python parity corpus, kill-switch tests that need a live engine, and
the randomised differential sweep. With the extension present, they run — and every other test then
exercises native masks and numeric prefixes too.

## Rust core (optional)

Building the accelerator requires a Rust toolchain and `maturin` or `setuptools-rust`, depending on the
crate. CI builds all three artefacts:

<CodeBlock language="bash" title="native builds" code={`cargo test -p veritas-core --all-targets
cargo build --release -p veritas-py
cargo build -p veritas-wasm --target wasm32-unknown-unknown`} copyable />

There are no C dependencies inside `veritas-core`; it uses no external crates.

## Troubleshooting

| Symptom | Cause | Fix |
| :--- | :--- | :--- |
| `ModuleNotFoundError: veritas` | Installed into a different interpreter/venv | Use the same binary for `pip` and `python` (`.venv/bin/python -m pip …`) |
| `doctor` says `reference` | Extension not built or not loadable | Expected on most machines; build it or keep using Python |
| `--strict` exits 1 | Native extension missing | This is the documented behaviour — use it only when you require native |
| `pip` cannot resolve `git+https` | No network / private mirror | Clone and use `pip install -e .` |
| Rust build fails | No toolchain | Not required: skip the accelerator and use the pure-Python engine |
| Z3 import errors | Extra not installed | `pip install "veritas-ai[z3] @ git+…"` or use `solver="nano"` |

More edge cases — open bounds, pattern fallbacks, numeric digit budgets — are documented on
[Troubleshooting & limits](/docs/getting-started/troubleshooting).

## Uninstall

```bash
pip uninstall veritas-ai
```

Nothing outside the environment is modified: no global config, no daemon, no database.
