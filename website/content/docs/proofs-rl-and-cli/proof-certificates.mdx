Every verified decode ships with a **tamper-evident SHA-256 witness digest** and an **offline-verifiable SMT-LIB2 proof script**. Verify with `veritas verify-proof` — zero backend storage required.

---

## What Is a Proof Certificate?

A `ProofCertificate` is a self-contained JSON object that proves:

1. The output satisfies all constraints
2. The SHA-256 witness digest matches the output
3. The SMT-LIB2 script is satisfiable (SAT)
4. Zero-DoF fields were computed deterministically

---

## ProofCertificate structure

A certificate is a JSON object with exactly these keys — `version`, `sha256`, `spec_sha256`,
`witness_sha256`, `smt2_sha256`, `witness`, `spec`, `smt2`, `smt2_complete`, `smt2_omitted` and
`metadata`:

<CodeBlock language="json" title="ticket_proof.json (abridged)" code={`{
  "version": "2.0",
  "sha256": "b05a9b6c8b7ecc11f0dfd232e09db1cbfdc2c39902a50624014e1957af7bc2cd",
  "spec_sha256": "fa7eb9478ab886630f7ae37c0c946c4e1f072481a55f670d69a1167251b5f66b",
  "witness_sha256": "354732bf8bb87825e25e52e8f64a3a2ba12a83db0332d398e2143073487c7b4c",
  "smt2_sha256": "fda1ac1aefa5e74f0689a44a3220d3f98e4b161aed274cf51baaa9071c16…",
  "witness": {"priority": 2, "sla_hours": 12},
  "spec": {"version": 3, "model": "Ticket", "variables": {...}, "requires": [...]},
  "smt2": "; veritas proof certificate (v2.0)\n(set-logic ALL)\n(declare-const priority Int)\n…",
  "smt2_complete": true,
  "smt2_omitted": [],
  "metadata": {}
}`} copyable />

### Fields

| Field | Type | Meaning |
| :--- | :--- | :--- |
| `version` | string | Certificate format, currently `"2.0"` — checked on load |
| `sha256` | hex | Digest over the certificate content; any edit breaks it |
| `spec_sha256` | hex | Digest of the embedded compiled spec |
| `witness_sha256` | hex | Digest of the witness (the concrete instance) |
| `smt2_sha256` | hex | Digest of the SMT-LIB2 script |
| `witness` | object | The values that were verified |
| `spec` | object | Versioned VIR payload, so re-checking needs no original schema |
| `smt2` | string | SMT-LIB2 rendering, bound to the spec and witness digests |
| `smt2_complete` | bool | Whether every constraint could be exported exactly |
| `smt2_omitted` | array | Constraints left out — still checked by the VIR evaluator |
| `metadata` | object | Free-form, empty unless you pass it |

<Callout variant="warn" title="Coverage is reported, never assumed">
`sqrt`, `quad_form` and other fragments SMT-LIB cannot express exactly are listed in `smt2_omitted`,
with `smt2_complete: false`. The certificate still verifies: `verify-proof` re-evaluates those
constraints from the embedded VIR and says so in the `smt2_coverage` check.
</Callout>

## `veritas verify-proof` CLI

<CodeBlock language="bash" code={`$ veritas verify-proof proof.json
certificate: VALID
  [ok] version: found '2.0', expected '2.0'
  [ok] sha256: content digest matches
  [ok] witness_sha256: witness digest matches
  [ok] smt2: SMT-LIB2 script present
  [ok] spec_sha256: embedded spec matches its digest
  [ok] constraints: PASS: 1 satisfied, 0 violated, 0 unevaluated
  [ok] smt2_coverage: complete SMT export
  [ok] smt2_binding: SMT script is bound to the embedded spec and witness
  [ok] portable_model: structural schema is portable`} copyable />

`--json` returns `{"ok": bool, "checks": [{name, ok, detail}], "errors": [], "report": {...},
"spec_sha256": "…"}`.

### Tamper test

Change one witness value and the digests stop agreeing. The constraints still pass — the edited
witness was still a legal instance — but the certificate is rejected, and the report says exactly
which bindings broke:

<CodeBlock language="bash" code={`$ veritas verify-proof tampered_proof.json     # witness.sla_hours: 12 -> 11
certificate: INVALID
  [ok] version: found '2.0', expected '2.0'
  [FAIL] sha256: digest mismatch or missing
  [FAIL] witness_sha256: witness digest mismatch
  [ok] smt2: SMT-LIB2 script present
  [ok] spec_sha256: embedded spec matches its digest
  [ok] constraints: PASS: 1 satisfied, 0 violated, 0 unevaluated
  [ok] smt2_coverage: complete SMT export
  [FAIL] smt2_binding: SMT script does not match spec/witness
  [ok] portable_model: structural schema is portable
# exit 1`} copyable />

<Callout variant="warn" title="Hashes are integrity, not authentication">
Anyone can recompute an unkeyed SHA-256. Bind verification to the spec you trust with
`vt.verify_proof(cert, expected_spec=portfolio)`, or sign the artifact in your own application.

</Callout>

## Why Proof Certificates Matter

| Scenario | Without Proof | With Proof Certificate |
| :--- | :--- | :--- |
| Audit compliance | "Trust me, the LLM output was correct" | "Here's the SHA-256 witness and SMT-LIB2 script" |
| Dispute resolution | Re-run the LLM and hope | Verify offline in seconds |
| Regulatory reporting | No artifacts | Self-contained proof artifact |
| Model comparison | Subjective | Objective: same constraints, same proof |
