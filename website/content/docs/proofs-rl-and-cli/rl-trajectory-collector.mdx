Every UNSAT branch is a rejected completion. Every repair is a chosen one. `VexxRLCollector` records
those pairs while you decode and exports them as training rows — with a digest so the dataset is
reproducible.

<Callout variant="warn" title="A record is not automatically a pair">
`record_conflict_branch(...)` without a chosen completion is an **incomplete** record. It is kept, but
`export_step_dpo()` skips it: a rejected branch with no accepted counterpart is not a preference pair.
Only `record_repair(...)` or `add_preference(...)` completes it.
</Callout>

<CodeBlock language="python" title="collect and export" code={`from vexx.rl.collector import VexxRLCollector

collector = VexxRLCollector()

# A branch that failed, and the completion that replaced it
record = collector.record_conflict_branch(
    state=None, clause=None, core_nodes=["weights.sum"],
    prompt="propose a portfolio",
    rejected='{"weights": {"AAPL": 0.5, "MSFT": 0.45, "NVDA": 0.3}}',
    margin=0.25,
)
collector.record_repair(record, chosen='{"weights": {"AAPL": 0.40, "MSFT": 0.35, "NVDA": 0.25}}')

# Or record a pair directly
collector.add_preference(
    prompt="propose a low-volatility portfolio",
    chosen='{"weights": {"AAPL": 0.45, "MSFT": 0.40, "NVDA": 0.15}}',
    rejected='{"weights": {"AAPL": 0.60, "MSFT": 0.20, "NVDA": 0.20}}',
    unsat_core=["volatility <= 0.20"],
)

dpo = collector.export_step_dpo("./traces")
print(dpo["num_records"], dpo["sha256"], dpo["manifest"])
# 2  <sha256>  ./traces/manifest.json`} copyable />

<Callout variant="info" title="Manifest, not vibes">
Each export writes a JSONL file plus a manifest containing the file digest and row count. That lets you
point at an exact dataset revision during training and reproduce the collection run.
</Callout>

## What gets exported

| Export | File | Rows |
| :--- | :--- | :--- |
| `export_step_dpo` | `step_dpo.jsonl` | `{prompt, chosen, rejected, metadata{unsat_core, violation_margin}}` |
| `export_grpo` | `process_grpo.jsonl` | one row per recorded step with its reward |

`export_step_dpo` refuses records where `prompt`, `chosen` or `rejected` is empty, or where
`chosen == rejected`. `total_conflicts` in the returned dict tells you how many raw records existed, so
the difference is auditable.

## Wiring it into a decode

from vexx.rl.collector import VexxRLCollector

collector = VexxRLCollector()
result = vx.generate(model=model, prompt="propose a portfolio", spec=portfolio)

if result.report.status != "PASS":
    collector.record_conflict_branch(
        core_nodes=result.report.unsat_core or [],
        prompt="propose a portfolio",
        rejected=result.raw,
        margin=0.1,
    )
# then complete the pair with the next verified attempt via record_repair(...)

## Limits

- This is **data plumbing**, not a trainer. No loss, no optimiser, no model.
- Rewards and margins are values you supply; the collector does not estimate them.
- Metadata is copied verbatim — never put credentials or personal data there.
- The `datasets` extra is only needed if you feed the exported files into Hugging Face tooling; the
  collector itself has no such dependency.
