| :--- | :--- | :--- |

## `vexx check-spec`

<CodeBlock language="bash" title="pre-flight, no tokens" code={`$ vexx check-spec ticket_spec.py
schema: ticket  (SAT)
  fields:   priority, sla_hours
  derived:  -
  requires: 1  derives: 0
  digest:   fa7eb9478ab886630f7ae37c0c946c4e1f072481a55f670d69a1167251b5f66b`} copyable />

A contradictory schema never gets a report — the compile step raises, the CLI prints the error and
exits 2:

<CodeBlock language="bash" code={`$ vexx check-spec window_spec.py
error: InfeasibleSpecError: Spec window is infeasible at pre-flight
# exit 2`} copyable />

<KeyValueTable
  rows={[
    { key: 'target', value: 'path.py[:name] or module[:name]', note: 'Name is only needed when a module declares several schemas' },
    { key: '--json', value: 'list of described specs', note: 'fields, derived, requires, derives, containers, zero_dof_rules, preflight, digest' },
  ]}
/>

<Callout variant="warn" title="UNKNOWN is exit 1, and it is not a failure">
For a schema whose witness cannot be constructed (a dynamic `dict` container, for example) the verdict
is `UNKNOWN` and the command exits 1, because it only reports success for a checked `SAT`. Use `--json`
and read `preflight.status` in CI rather than treating 1 as "the spec is broken": `UNSAT` never gets
this far, and a real violation shows up in `verify`.
</Callout>

## `vexx verify-proof`

<CodeBlock language="bash" title="offline, every check named" code={`$ vexx verify-proof ticket_proof.json
certificate: VALID
  [ok] version: found '2.0', expected '2.0'
  [ok] sha256: content digest matches
  [ok] witness_sha256: witness digest matches
  [ok] smt2: SMT-LIB2 script present
  [ok] spec_sha256: embedded spec matches its digest
  [ok] constraints: PASS: 1 satisfied, 0 violated, 0 unevaluated
  [ok] smt2_coverage: complete SMT export
  [ok] smt2_binding: SMT script is bound to the embedded spec and witness
  [ok] portable_model: structural schema is portable`} copyable />

Coverage is reported, not implied: a certificate whose SMT export omits a constraint still verifies,
and the check says so — `SMT export omits 1 constraint(s); VIR verification remains authoritative`.

## `vexx inspect`

<CodeBlock language="bash" code={`$ vexx inspect trace.json --out report.html
trace: trace.json
  status: PASS
  steps: 25  backtracks: 1  jump-forward fields: 6
  report: report.html`} copyable />

The viewer is a single standalone HTML file — no server, no assets. Without `--out` the report is written
next to the trace with an `.html` suffix. `--json` returns the trace path, the HTML path and the whole
telemetry dictionary.

## `vexx synth`

<CodeBlock language="bash" code={`$ vexx synth --from-json examples.json --out generated_schema.py
wrote generated_schema.py

$ vexx check-spec generated_schema.py
schema: synthesized  (SAT)
  fields:   sku, quantity, unit_price
  derived:  -
  requires: 2  derives: 0`} copyable />

The generated module is a normal `@vx.verified_schema` with bounded ranges inferred from the examples:

<CodeBlock language="python" title="generated_schema.py (excerpt)" code={`class Synthesized(BaseModel):
    sku: str = 'ABC-1234'
    quantity: int = 2
    unit_price: float = 19.5

@vx.verified_schema()
def synthesized(p: Synthesized):
    vx.require((1 <= p.quantity) & (p.quantity <= 5))
    vx.require((-19.325 <= p.unit_price) & (p.unit_price <= 263.575))`} copyable />

## Exit codes

| Code | Meaning | When |
| :--- | :--- | :--- |
| 0 | Success | PASS, VALID, SAT, healthy `doctor` |
| 1 | Failed check | FAIL, invalid certificate, `UNKNOWN`/`UNSAT` pre-flight, `doctor --strict` without the accelerator |
| 2 | Bad input | `InfeasibleSpecError` at import, missing argument, unreadable file |

<Callout variant="tip" title="Scripting without guessing">
`--json` is available on all six commands, and stdout carries only the payload while errors go to
stderr. In CI, parse `status`/`ok`/`preflight.status` rather than matching English strings.

</Callout>
