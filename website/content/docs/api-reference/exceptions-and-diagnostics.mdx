## The hierarchy, as it ships

The exceptions come from four modules and inherit from three different bases, which matters when you
write an `except` clause:

<CodeBlock language="text" title="vexx 2.1.0" code={`ValueError
├── InfeasibleSpecError        vexx.compiler.preflight   .conflicts  .relaxation
├── CertificateError           vexx.proof.certificate
├── InstanceFormatError        vexx.instance
├── JSONSyntaxError            vexx.json_pda
└── TranspileError             vexx.compiler.ast_transpiler

Exception
├── CircularDerivationError    vexx.compiler.dependency_graph
└── VerificationError          vexx.instance             .report

RuntimeError
└── DecodeError                vexx.decode
    ├── ModelProtocolError     model lacks next_logits()
    └── DeadEnd                .field_name  .reason`} copyable />

<KeyValueTable
  rows={[
    { key: 'InfeasibleSpecError', value: 'Compilation and pre-flight', note: 'Contradictory spec. .conflicts holds constraint indices; .relaxation is a dict with details, hints and a suggestion' },
    { key: 'CircularDerivationError', value: 'compile() / import', note: 'Two derive rules depend on each other' },
    { key: 'VerificationError', value: 'report.raise_if_failed(), verified tools', note: 'An instance failed. The message repeats the report summary and the first violations' },
    { key: 'CertificateError', value: 'verify_proof()', note: 'Certificate cannot be parsed, a digest does not match, or the embedded spec is malformed' },
    { key: 'InstanceFormatError', value: 'verify_instance()', note: 'The instance is not JSON, or not an object' },
    { key: 'JSONSyntaxError', value: 'JSON pushdown automaton', note: 'A prefix that cannot be extended to valid JSON' },
    { key: 'DecodeError', value: 'vx.generate() / session.run()', note: 'Base for generation failures; ModelProtocolError and DeadEnd are the concrete cases' },
  ]}
/>

<Callout variant="warn" title="Two classes are called VerificationError">
`vexx.VerificationError` (from `vexx.instance`) reports a failed instance and exposes `.report`.
`vexx.bridges.VerificationError` is a separate `RuntimeError` raised by `patch_openai`. Catch them
explicitly rather than with a bare `except Exception`.
</Callout>

## Catching the right thing

<CodeBlock language="python" title="compile-time vs run-time failures" code={`import vexx as vx

# A @vx.verified_schema module compiles and pre-flights at import time.
try:
    from portfolio_spec import portfolio
except vx.InfeasibleSpecError as exc:
    print(exc.conflicts)                  # [0, 1] -> constraint indices
    print(exc.relaxation["hints"])        # ['constraint #0 \`end >= 8\` participates in a conflict', ...]
    raise SystemExit(2)

report = portfolio.verify({"weights": {"AAPL": 0.90, "MSFT": 0.05, "NVDA": 0.05}})

if not report.ok:
    print(report.status)                  # FAIL
    print(report.violations)              # [ConstraintOutcome(index=2, kind='require', ...)]
    report.raise_if_failed()              # raises vx.VerificationError`} copyable />

The message from a real failure is short enough to paste into a bug report:

<CodeBlock language="text" code={`VerificationError
FAIL: 5 satisfied, 1 violated, 0 unevaluated
  violated: forall(weights.values(), (0.05 <= w ∧ w <= 0.5))`} copyable />

## VerificationReport

`report` is a dataclass, not a dict. These are the fields and helpers you can rely on:

## Decode telemetry

`vx.generate(...)` returns a `VerifiedResult` whose `telemetry` dict is `DecodeTelemetry.as_dict()`. The
keys are stable, and unknown keys never appear — so a dashboard that reads them keeps working:

<CodeBlock language="python" code={`result = vx.generate(model=model, prompt="propose a portfolio", spec=portfolio)

result.raw          # exact JSON stream that was decoded
result.report.status
result.telemetry["jump_forward_fields"]   # fields spliced with zero forward passes
result.telemetry["backtracks"]
result.telemetry["elapsed_ms"]`} copyable />

The remaining keys — `string_mask_prunes`, `format_witnesses`, `twist_adjustments`, `reasoning_chars`,
`mined_equations` — are counters with the same rules: they increment, never guess.

## CLI exit codes

The CLI has three outcomes, not four. There is no separate "pre-flight gate" code:

<KeyValueTable
  rows={[
    { key: '0', value: 'Success', note: 'PASS instance, VALID certificate, SAT pre-flight, healthy doctor' },
    { key: '1', value: 'Verification failure', note: 'FAIL / UNSAT / incomplete certificate, and doctor --strict without the accelerator' },
    { key: '2', value: 'Invalid input', note: 'InfeasibleSpecError at compile time, missing --from-json, unreadable file' },
  ]}
/>

<CodeBlock language="bash" title="health checks that fail loudly" code={`python -m vexx doctor --strict            # exit 1 unless the native extension is loaded
python -m vexx verify spec.py instance.json
python -m vexx verify-proof proof.json`} copyable />

<Callout variant="info" title="There is no verbose flag">
Diagnostics are flags, not environment variables: `--json` on every subcommand, `--strict` on `doctor`,
and `VEXX_NO_NATIVE=1` if you need to pin the reference engine per call. `VEXX_VERBOSE` does not
exist.
</Callout>
