Cartridges are **plain Python modules with deterministic checks**. They do not change the decoder and
they are not symbolic DSL predicates; they are concrete reference implementations you call on the
verified object — in a guard, a test, an audit script, or a `vt.verified_tool` handler.

<Callout variant="info" title="Two layers, one spec">
Use the DSL (`vt.require`, `vt.dot`, `vt.quad_form`, `vt.forall`) for constraints that must hold
*during* decoding. Use cartridges for domain logic that is easier to express as code — SMILES parsing,
SQL tokenisation, scheduling feasibility, dimensional algebra — then run it on the `PASS` object.
</Callout>

## The nine modules

| Module | Concrete checks | Detail |
| :--- | :--- | :--- |
| `quant` | Simplex and concentration limits, covariance PSD, portfolio statistics, Black–Scholes, implied volatility, no-arbitrage, accounting identities | [Finance](/docs/cartridges/quantitative-finance) |
| `sql` | Tokenisation, table/column/alias resolution, foreign keys, tenant predicates, read-only enforcement | [SQL safety](/docs/cartridges/sql-and-database-safety) |
| `sec` | Declared tools, preconditions/effects, budgets, snapshots, LTLf policy evaluation | [Security & IAM](/docs/cartridges/security-and-iam-policies) |
| `or_sched` | Precedence DAG, earliest schedule, deadlines, interval capacity, critical path | [Scheduling](/docs/cartridges/operations-research-scheduling) |
| `stat` | Probability simplex, Fréchet bounds, Bayes consistency, covariance PSD, d-separation | [Statistics](/docs/cartridges/statistics-and-distributions) |
| `phys` | Rational-exponent dimensional algebra over $\mathbb{Q}^7$, AST equation checks, quantities | [Physics](/docs/cartridges/physics-dimensional-analysis) |
| `chem` | SMILES tokenisation/parsing, ring closures, charges, implicit hydrogens, valence, formula, weight | [Chemistry](/docs/cartridges/chemistry-smiles) |
| `code` | Scope-aware undefined identifiers, literal division by zero, literal index bounds, syntax errors | [Code analysis](/docs/cartridges/code-analysis-and-synthesis) |
| `code_synth` | The implementation module; `code` re-exports it (`from .code_synth import *`) | [Code analysis](/docs/cartridges/code-analysis-and-synthesis) |

## The composition pattern

A single object can be checked by several domains. Verify the math with the engine, then run the domain
guards on the concrete result:

<CodeBlock language="python" title="one verified object, several domain guards" code={`import veritas as vt
from veritas.cartridges import quant, sec, sql

report = trading_action.verify(candidate)
report.raise_if_failed()

# finance: weights + concentration
assert quant.portfolio_weights_valid(
    candidate["weights"], allowed={"AAPL", "MSFT", "NVDA"}, lo=0.05, hi=0.50
)
assert quant.concentration_ok(candidate["weights"], max_weight=0.50)

# security: the policy that governed the tools
state = sec.WorldState()
state.declare_tool("transfer", requires=["authenticated"], cost=10.0, budget_key="usd")
state.assert_fact("authenticated")
assert state.can_call("transfer")

# SQL: read-only, tenant-scoped, known tables
verifier = sql.SqlVerifier({"orders": ["id", "tenant_id", "total"]})
result = verifier.verify(candidate["query"])
assert result.ok, result.errors`} copyable />

<Callout variant="warn" title="Guards are not the decoder">
A cartridge guard runs **after** the object exists. It cannot mask a token or rewind a branch. If a
condition must be enforced during decoding, express it in the schema with `vt.require`; keep cartridges
for domain logic that is clearer as code.
</Callout>

## When a cartridge is the right tool

<FeatureGrid>
  <Feature title="Parsing is the constraint" icon="database">
    SMILES, SQL and dimensional expressions need real parsers. The cartridges provide them without
    pulling NumPy or z3 into the hot path.
  </Feature>
  <Feature title="You need a readable audit" icon="check">
    Returning `SqlVerification` or `CodeReport` gives an operator something to read — errors, warnings,
    line and column.
  </Feature>
  <Feature title="You already have the object" icon="cpu">
    Post-hoc checks are cheap and composable: run them in your service, in CI, or in a nightly audit of
    stored generations.
  </Feature>
  <Feature title="You need in-decode enforcement" icon="layers">
    Use the DSL. `vt.require` compiles into the mask and contractors, which is the only way to prevent
    rather than detect.
  </Feature>
</FeatureGrid>
