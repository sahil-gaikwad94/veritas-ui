An LLM asked for a schedule produces something that looks like a schedule. `or_sched` checks that it
**is** one: acyclic precedence, resource capacity, release times and deadlines.

## Build and validate a plan

<CodeBlock language="python" title="a small job shop" code={`from veritas.cartridges.or_sched import SchedulingProblem

plan = SchedulingProblem(horizon=12.0)
plan.add_task("design", duration=2.0, resource="engineer", demand=1, deadline=4.0)
plan.add_task("build", duration=3.0, predecessors=["design"], resource="engineer", demand=1)
plan.add_task("test", duration=2.0, predecessors=["build"], resource="tester", demand=1)
plan.set_capacity("engineer", 1)
plan.set_capacity("tester", 1)

print(plan.topological_order())      # ['design', 'build', 'test']
print(plan.earliest_schedule())      # {'design': 0.0, 'build': 2.0, 'test': 5.0}
print(plan.makespan())               # 7.0
print(plan.critical_path())          # (7.0, ['design', 'build', 'test'])

assert plan.feasible()
assert plan.validate(plan.solve()) == []

bad = {"design": 0.0, "build": 0.0, "test": 7.0}
for violation in plan.validate(bad):
    print(violation.as_dict())
# {'kind': 'precedence', 'message': 'build starts before design ends', 'tasks': ['design', 'build']}`} copyable />

<Callout variant="info" title="Replace the solver, keep the verifier">
`earliest_schedule` and `solve` are a deterministic baseline. If your planner produces a different
answer, pass its `starts` mapping to `validate` — the checks do not care who produced the schedule.
</Callout>

## Free-standing checks

<CodeBlock language="python" code={`from veritas.cartridges.or_sched import no_overlap, precedence_ok, capacity_ok

assert no_overlap([(0, 2), (2, 4), (4, 5)])
assert not no_overlap([(0, 2), (1, 3)])          # touching is fine, overlap is not

assert precedence_ok(
    starts={"a": 0, "b": 2},
    durations={"a": 2, "b": 1},
    preds={"b": ["a"]},
)
assert capacity_ok(loads=[1, 2, 1], capacity=2)
assert not capacity_ok(loads=[1, 2, 3], capacity=2)`} copyable />

## Enforce it during decoding

Scheduling is mostly linear, so the constraints you cannot afford to violate belong in the DSL:

<CodeBlock language="python" title="mask the wrong start times" code={`import veritas as vt

@vt.verified_schema()
def schedule(s: Schedule):
    vt.require(vt.forall(s.starts.values(), lambda t: t >= 0))
    vt.require(s.starts["build"] - s.starts["design"] >= s.durations["design"])
    vt.require(s.starts["test"] - s.starts["build"] >= s.durations["build"])
    vt.require(vt.sum(s.engineer_loads) <= 1.0)`} copyable />

Use `or_sched` afterwards for the parts that are combinatorial — capacity over intervals and the
critical path.

## Limits

- Durations are deterministic; there is no stochastic or resumable scheduling.
- Capacity checks assume piecewise-constant demand over `[start, start + duration)`.
- `solve()` is an earliest-start heuristic, not a global optimiser. It is a reference, not an oracle.
- Resource calendars, setup times and sequence-dependent changeovers are out of scope.
