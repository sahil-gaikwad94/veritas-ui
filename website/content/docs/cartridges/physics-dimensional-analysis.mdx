Dimensions are a type system for equations. `phys` represents them as a vector in $\mathbb{Q}^7$ over
the SI base quantities — length, mass, time, current, temperature, amount and luminous intensity — so
fractional exponents are exact and multiplication is vector addition.

<Callout variant="info" title="Exact rational exponents">
`pow_dim(AREA, Fraction(1, 2))` stays a fraction. No floating-point drift turns a valid equation into a
mismatch, and square roots of dimensions behave the way algebra says they should.
</Callout>

## Check an equation

<CodeBlock language="python" title="F = m·a, and a wrong E = m·v" code={`from veritas.cartridges.phys import (
    FORCE, MASS, ACCELERATION, ENERGY, VELOCITY,
    check_equation, check_expression, dimension_of_expression,
)

symbols = {"F": FORCE, "m": MASS, "a": ACCELERATION, "E": ENERGY, "v": VELOCITY}

print(check_equation("F", "m*a", symbols))
# (True, 'dimensionally consistent: L·M·T^-2')

print(check_equation("E", "m*v", symbols))
# (False, 'dimension mismatch: LHS is L^2·M·T^-2, RHS is L·M·T^-1')

print(dimension_of_expression("m*a**2", symbols))   # Dim(L^2·M·T^-2)
print(check_expression("0.5*m*v**2", symbols))      # (True, 'L^2·M·T^-2')`} copyable />

`check_equation` parses both sides as Python expressions, so `**`, parentheses and rational exponents
work as expected. Anything it cannot parse returns `(False, reason)` instead of raising.

## Dimension algebra

<CodeBlock language="python" title="products, powers and square roots stay exact" code={`from fractions import Fraction
from veritas.cartridges.phys import (
    LENGTH, TIME, MASS, VELOCITY, ACCELERATION, FORCE,
    mul_dim, div_dim, pow_dim, homogeneous, is_dimensionless, dim_to_str,
)

assert homogeneous(mul_dim(ACCELERATION, TIME), VELOCITY)
assert homogeneous(div_dim(FORCE, ACCELERATION), MASS)

area = mul_dim(LENGTH, LENGTH)
print(dim_to_str(area))                        # L^2
print(pow_dim(area, Fraction(1, 2)))           # (1, 0, 0, 0, 0, 0, 0)
print(is_dimensionless(div_dim(LENGTH, LENGTH)))   # True`} copyable />

<Callout variant="info" title="Quantity is a pair, not a unit system">
`Quantity(value, dim)` stores a value with its dimension and supports construction plus same-dimension
addition and subtraction. Products and powers are expressed with `mul_dim`, `div_dim` and `pow_dim`;
there is no unit conversion layer.
</Callout>

## What it does not do

- **No unit conversion.** Dimensions are not units: `Quantity(1, LENGTH)` does not know metres from
  inches. Convert before constructing.
- **No value solving.** It checks dimensional consistency, not numerical equality or solvability.
- **No dimensional inference for arbitrary code.** Only expressions it can parse as Python ASTs.
- **Constants are a fixed convenience set.** Define your own dimensions with `_dim`/`add_dim` if you
  need more.
