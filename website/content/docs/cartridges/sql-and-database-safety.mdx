Generated SQL is a security boundary. `vexx.cartridges.sql` verifies one read-only `SELECT`
against your declared catalog using `sqlglot` — the same parser dependency the core package already
ships with.

<Callout variant="warn" title="Absence of evidence">
This verifier rejects what it can prove unsafe and warns about constructs it cannot resolve. It is not
a SQL sandbox and it is not a substitute for database permissions. Run generated SQL with a read-only
role and row-level security.
</Callout>

## What it enforces

<FeatureGrid>
  <Feature title="Read-only by default" icon="shield">
    `INSERT`, `UPDATE`, `DELETE`, DDL and multi-statement input are rejected when `read_only=True`.
  </Feature>
  <Feature title="Real names only" icon="database">
    Every table, column and alias is resolved against the catalog. Unknown identifiers are errors, not
    guesses.
  </Feature>
  <Feature title="Tenant isolation" icon="lock">
    When required, the predicate must be a top-level conjunctive equality on the tenant column — not a
    substring and not an `OR` branch.
  </Feature>
  <Feature title="Honest structure" icon="check">
    Subqueries, CTEs, `UNION` and set operations are outside the supported subset and are refused
    explicitly.
  </Feature>
</FeatureGrid>

## Usage

<CodeBlock language="python" title="catalog + verifier" code={`from vexx.cartridges.sql import SqlCatalog, SqlVerifier, ForeignKey

catalog = SqlCatalog(
    tables={
        "orders": ["id", "tenant_id", "user_id", "total", "created_at"],
        "users": ["id", "tenant_id", "email"],
    },
    foreign_keys=[ForeignKey("orders", "user_id", "users", "id")],
    tenant_column="tenant_id",
    require_tenant=True,
)

verifier = SqlVerifier(catalog, read_only=True)

result = verifier.verify(
    "SELECT o.id, o.total FROM orders AS o "
    "JOIN users AS u ON o.user_id = u.id "
    "WHERE o.tenant_id = 'acme'"
)
print(result.as_dict())
# {'ok': True, 'errors': [], 'warnings': [...],
#  'tables': ['orders', 'users'], 'columns': ['id', 'total'],
#  'has_tenant_filter': True}`} copyable />

## Calls that should fail

<CodeBlock language="python" title="the failures you want to see" code={`# unknown table and unknown column
assert not verifier.verify("SELECT secret FROM payroll").ok

# write attempt in a read-only pipeline
assert not verifier.verify("DELETE FROM orders WHERE id = 1").ok

# tenant filter hidden behind OR — not a top-level conjunct
assert not verifier.verify(
    "SELECT id FROM orders WHERE tenant_id = 'a' OR total > 0"
).ok

# subquery is outside the supported subset
assert not verifier.verify(
    "SELECT id FROM orders WHERE id IN (SELECT id FROM users)"
).ok`} copyable />

<Callout variant="info" title="Structural warnings">
Constructs the verifier can parse but not fully resolve — expressions it does not model, unusual
functions — appear in `warnings`. Treat warnings as review items: `ok` means "no proven violation",
not "no risk".
</Callout>

## Wiring it into a pipeline

<CodeBlock language="python" title="guard before execution" code={`def safe_query(sql: str) -> str:
    result = verifier.verify(sql)
    if not result.ok:
        raise ValueError(f"unsafe query: {result.errors}")
    return sql

report = text_to_sql.verify(generated)      # shape + arithmetic
report.raise_if_failed()
safe_query(generated["sql"])                # catalog + security`} copyable />

## Limits

- One `SELECT` statement only; no `WITH`, `UNION` or nested subqueries.
- Tenant isolation is checked syntactically (top-level conjunct on `tenant_id`), not semantically
  against data.
- Comment and string stripping happens before tokenisation, so a column name inside a string literal is
  not mistaken for a reference.
- The catalog is whatever you declare. If it drifts from the real schema, verification drifts with it.
