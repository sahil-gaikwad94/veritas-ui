Generated Python is executable text. `code` (an alias of `code_synth`) parses it and reports what it can
prove wrong before anything runs: undefined names under real scoping rules, literal division by zero,
out-of-range literal indices and syntax errors.

<Callout variant="warn" title="Static checks, not a sandbox">
This is an AST pass, not taint analysis, not a capability system, and not a substitute for running
generated code in an isolated process. It catches a useful class of mistakes; it does not prove
safety.
</Callout>

<FeatureGrid>
  <Feature title="Real scopes" icon="layers">
    Function parameters, locals, comprehension targets, `global`/`nonlocal`, class bodies and imports are
    tracked; builtins are seeded, not guessed.
  </Feature>
  <Feature title="Location-aware" icon="check">
    Every issue carries line and column, so a repair loop gets a precise target.
  </Feature>
  <Feature title="Literal mistakes" icon="shield">
    `1 / 0`, negative or oversized constant indices and syntax errors are reported without executing a
    single statement.
  </Feature>
  <Feature title="Alias kept stable" icon="git">
    `veritas.cartridges.code` re-exports `code_synth`, so both import paths are supported.
  </Feature>
</FeatureGrid>

## Verify a generated function

<CodeBlock language="python" title="undefined name and division by zero" code={`from veritas.cartridges.code import verify_python_source

clean = verify_python_source(
    "def total(xs):\\n"
    "    return sum(xs) / len(xs)\\n"
)
print(clean.ok)          # True

broken = verify_python_source(
    "def total(xs):\\n"
    "    return sum(xs) / missing\\n"
)
print(broken.as_dict())
# {'ok': False,
#  'errors': [{'kind': 'undefined_identifier',
#              'message': "undefined identifier 'missing'",
#              'line': 2, 'column': 15}],
#  'warnings': []}

divide = verify_python_source("def f(x):\\n    return 1 / 0\\n")
print(divide.errors[0].kind)     # division_by_zero`} copyable />

## Small predicates

<CodeBlock language="python" title="for repair loops and tests" code={`from veritas.cartridges.code import (
    scope_safe, no_division_by_zero, array_bounds_ok, type_compatible,
)

assert scope_safe({"x", "y"}, {"x"})
assert not scope_safe({"x"}, {"x", "z"})

assert no_division_by_zero([1, 2, 0.5])
assert not no_division_by_zero([1, 0])

assert array_bounds_ok(0, 3)
assert not array_bounds_ok(3, 3)

assert type_compatible("int", "float")
assert not type_compatible("str", "float")`} copyable />

## The repair loop

<CodeBlock language="python" title="report errors back to the model, then re-check" code={`from veritas.cartridges.code import verify_python_source

source = generate_code(prompt)
for attempt in range(3):
    report = verify_python_source(source)
    if report.ok:
        break
    feedback = "\\n".join(f"{e.line}:{e.column} {e.message}" for e in report.errors)
    source = repair(prompt, source, feedback)
else:
    raise RuntimeError("could not produce code that passes static checks")`} copyable />

<Callout variant="info" title="Pair it with a spec">
Static checks say nothing about behaviour. If the generated code must compute a specific value, express
that in the schema with `vt.derive` / `vt.require` and verify the produced result — then run the code in
isolation.
</Callout>

## Limits

- Undefined-name detection follows Python scoping for the constructs it models; dynamic tricks
  (`eval`, `exec`, `globals()` mutation, `__getattr__`) defeat static analysis, as they do any linter.
- Division-by-zero detection covers **literal** divisors, not values computed at runtime.
- `type_compatible` is a small compatibility table for common annotations, not a type checker.
- Nothing here executes code, imports modules or inspects third-party APIs.
